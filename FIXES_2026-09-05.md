# POS Fixes — 2026-09-05

## 1. User switching in the POS header
- Restored **تبديل المستخدم** for `admin` and `cashier` inside the POS top bar.
- This is visible on mobile where the global AppShell header is intentionally hidden on the sales screen.
- The existing desktop AppShell switch-user button remains unchanged.
- Switching user continues through the existing logout/login flow and does not close the register session in the database.

## 2. Shift closing numeric keypad
- Shift open/close dialogs now use `modal={false}` so the centralized numeric keypad can receive touch/pointer events outside the Radix dialog on Android/WebView.
- The same correction was applied to numeric-pad dialogs in the register screen (opening, closing, cash movement).

## 3. Legacy local database repair
- Added a canonical repair pass to `src/lib/db/client.ts`.
- Older local databases that contain legacy versions of `customer_payments`, `expenses`, `cash_ledger`, `sales`, or `purchases` now receive missing `register_session_id` columns automatically.
- Added the required session indexes.
- Existing data is preserved; no database reset is required.
- This fixes the `no such column: register_session_id` error during shift closing.

## 4. Product cards
- Product cards remain the entire add button; there is no separate "إضافة" label/button.
